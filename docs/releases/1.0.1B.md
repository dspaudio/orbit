# ORBIT 1.0.1B: adjustable Bluetooth audio buffer

This FM-1 Bluetooth build follows [ORBIT 1.0.B](1.0.B.md). The regular `orbit.fwsc` remains ORBIT 1.0.0; the new `orbit-ble.fwsc` identifies itself as **ORBIT 1.0.1B** with the same `FM-1_900` install identity.

**GLO > BT BUFFER** now lets KNOB 1 choose a 46, 58 or 70 ms phone-audio prebuffer. The old fixed 46 ms setting remains the minimum; **58 ms is the default**. A larger buffer gives incoming audio more time to arrive but adds latency. The FM-1 saves the choice as a device setting after playback and phone audio stop. It survives project changes and uses a reserved byte in the existing BLM1 Bluetooth settings record, without changing its layout or stored phone pairing keys. Older records without a buffer selection start at 58 ms.

Bluetooth MIDI and phone pairing work as described in the [1.0.B notes](1.0.B.md). The melodic sample replacements, original sampled drums, user samples, ORP8 projects and OPB3 preset banks are unchanged. The [web emulator](https://dspaudio.github.io/orbit-web-emu/) plays the firmware sound engine; browser Bluetooth audio is not emulated.

The Bluetooth pi32v2 package built and passed the focused A2DP and UI tests. It was written to an FM-1, reached 100%, rebooted and answered `FELUCCA ORBIT 1.0.1B` through USB MIDI. The device owner tested the installed firmware and approved this release. The host check has one pre-existing macOS-only IRQ compilation failure; the BLE disassembly exceeds three existing target-cost estimates. Neither host tests nor this installation measure Bluetooth latency, audio timing under radio load or runtime memory high-water. Commands, package checksum and measurements are in the [validation record](../VALIDATION.md#orbit-101b-bluetooth-release-2026-11-04).
