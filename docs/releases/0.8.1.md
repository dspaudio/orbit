# ORBIT 0.8.1

**SAMPLE retriggers, drum voice allocation, live-held POLY notes and MIDI fixes.**

This release ports selected **SLOOP 2.8 / 2.8.3 behavior**, with credit
and thanks to the SLOOP authors. The ports use the SLOOP 2.8 snapshot
`b77bf55e3bf804665b8f5dffb5955bd8443311f0` and SLOOP 2.8.3 commit
`5eb24c1dc18261a85c193e8b28318944690e58fd`; the clock estimator in the
2.8 snapshot originated in ancestor `beab3f6`.

The default FM-1 package was installed on **2026-10-28**. The device owner
confirmed normal screen and basic playing operation and approved release.
Official firmware assets are **FM-1 only**: `orbit.fwsc` and `SHA256SUMS`.

## Sound and performance fixes

- **SAMPLE retriggers:** a sounding voice fades out before restarting
  from silence, so ATK applies to the new note. Tests cover same-note and
  other-note POLY, MONO, LEGATO and UNISON. Reusing a fading voice respects
  the shared eight-voice budget.
- **Drums:** use a free voice first. When all six drum voices are busy,
  reuse the same sound's voice; otherwise steal the oldest non-kick, or
  the oldest kick if all voices are kicks. Kick protection uses notes
  35/36. Existing hat choke and declick tails remain in place.
- **Live-held POLY protection:** sequencer gates, steps, ratchets and
  outgoing slides leave a player's held pitch alone while other pattern
  pitches continue. Releasing a key leaves a sequencer-owned note playing
  until its gate ends. This is runtime ownership, not stored continuation:
  recorded playback can still shorten a held bass beneath later notes.
- **USB/TRS MIDI overflow:** after the shared input queue loses a note
  message, accepted packets are drained and MIDI-held notes are released.
  Distinct locally held pitches survive; sustain defers release until
  pedal-up.
- **External MIDI clock:** average eight recent beat durations to reduce
  jitter. A tempo jump of at least 5 BPM is followed on the first completed
  beat, not the first individual clock pulse.

## Layers and USB rescue

A held layer page appears after **0.35 s** rather than flashing during a
quick tap. Using a layer control while holding the button still opens it
immediately. Host tests check no page during or after a 0.2 s hold, display
at 0.4 s, and immediate display on knob use.

The early OCT- rescue scan now powers the FM-1 key matrix through the HAL
backlight helper before reading it. The software recovery test and target
register-access check pass. Physical **OCT- at power-on rescue has not
been tested**.

## Storage and build

**ORP8 projects and OPB3 USER banks are unchanged.** The `step_t` layout
and flag meanings remain unchanged, as does editor protocol 13. No stored
per-note continuation feature is added.

Use the default FM-1 build:

```sh
sh build.sh
```

The binary embeds `FELUCCA ORBIT 0.8.1` and retains install identity
**FM-1_900**. Do not use `--release`. See
[BUILDING.md](../../BUILDING.md) for the build environment and a local
installer-site example with `--version 0.8.1`.

The default is **`FELUCCA_SLICE=0`**. These results cover SAMPLE, not
SLICE; neither the optional SLICE build nor its retrigger behavior was
validated.

## Validation and hardware status

The default pi32v2 build, target-budget checks, full host suite, native
preview and separate web suite passed. The full suite includes the
10-minute simulated soak, stress and ASan/UBSan checks. All **218 audio
renders** match the reviewed goldens: five SAMPLE renders changed because
of retrigger fades and one GM drum render changed because of allocation;
the other 212 are unchanged. There were no health, voice/routing,
CPU-budget or crash failures in the regression run.

`tools/orbit_check.py` returned **exit 1: 34 PASS / 1 FAIL**. Its sole
failure is the existing macOS `irq_init_test` compilation limitation:
Mach-O section syntax and unavailable `MAP_FIXED_NOREPLACE`. This is not
an all-green run of that command.

The package is **610032 bytes**, SHA-256:

```text
77fd12eefc0c2e156a5bea73c0856b2279166068452d2b30a76d358c11b1149c
```

The app is 566360 bytes and the loader is 6876 bytes. Static RAM
`.data + .bss` uses **97544/98304 bytes, leaving 760 B in that region**,
not 760 B of total runtime free RAM. The pool is a separate region using
333948/344064 bytes, leaving 10116 B; user/supervisor stacks are separately
reserved. Actual stack high-water usage is unmeasured. These static
figures do not prove hardware timing. See the
[validation record](../VALIDATION.md#orbit-081-release-package-2026-10-28)
for commands, budgets and render attribution.
